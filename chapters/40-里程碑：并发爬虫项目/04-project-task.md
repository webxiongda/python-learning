# 第40章：里程碑：并发爬虫项目 — 项目任务

## 项目名称

异步网页状态采集器

## 目标

综合练习 threading、multiprocessing、asyncio、aiohttp、日志与性能意识。项目不追求复杂爬取规则，重点是并发控制、超时、重试、限速、结果持久化和失败可观察。

## 交付目录

在 `projects/chapter-40/` 下完成：

```text
projects/chapter-40/
├── README.md
├── crawler/
│   ├── __init__.py
│   ├── config.py
│   ├── fetcher.py
│   ├── runner.py

│   └── report.py
├── tests/

│   └── test_report.py
└── urls.txt
```

## 功能要求

- 从 `urls.txt` 读取 URL 列表。
- 使用 `aiohttp` 并发请求，支持最大并发数配置。
- 对单个请求支持超时、重试和失败原因记录。
- 输出每个 URL 的状态码、耗时、内容长度、错误信息。
- 保存结果为 JSON 或 CSV。
- 生成汇总报告：成功数、失败数、平均耗时、最慢 URL。

## 设计约束

- 并发数量必须可配置，默认不超过 5。
- 不抓取需要登录或绕过反爬的网站。
- 网络请求和结果统计分层实现，便于测试。
- 日志中不能只写“失败”，必须包含 URL、异常类型和耗时。

## 测试要求

- 测试不要依赖真实外网，使用 fake fetcher 或本地 mock。
- 必测场景：全部成功、部分失败、超时、空 URL 文件、重复 URL。
- 报告统计函数必须可单独测试。

## 阶段拆分

1. **同步原型**：先写一个单 URL 请求函数，确认返回结构。
2. **异步并发**：用 `asyncio.gather` 和信号量限制并发。
3. **可靠性**：加入超时、重试、失败原因和日志。
4. **输出报告**：把结果保存为文件，并生成汇总统计。
5. **测试替身**：抽象 fetcher，让测试可以不访问真实网络。

## 完成定义

这个项目完成时，你应该能解释清楚：

- 并发数为什么不能无限大。
- 超时、重试和限速分别解决什么问题。
- 为什么测试不应该依赖真实外网。
- `asyncio` 适合 IO 密集任务，而不是直接加速 CPU 密集任务。
- 日志里哪些字段能帮助定位线上失败。
