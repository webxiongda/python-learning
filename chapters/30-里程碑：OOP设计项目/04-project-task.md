# 第30章：里程碑：OOP设计项目 — 项目任务

## 项目名称

图书馆管理系统（OOP + 测试）

## 目标

用面向对象方式设计一个小型图书馆系统，综合练习类、继承、多态、魔术方法、属性、抽象类、数据类、枚举、设计模式和 pytest。

## 交付目录

在 `projects/chapter-30/` 下完成：

```text
projects/chapter-30/
├── README.md
├── library/
│   ├── __init__.py
│   ├── entities.py
│   ├── repositories.py
│   ├── services.py
│   └── policies.py
└── tests/
    ├── test_entities.py
    ├── test_services.py
    └── test_policies.py
```

## 功能要求

- 实体：`Book`、`Member`、`Loan`，使用 dataclass 或普通类均可，但字段必须清晰。
- 枚举：图书状态、会员等级、借阅状态。
- 借阅规则：普通会员最多借 3 本，高级会员最多借 6 本。
- 业务流程：添加图书、注册会员、借书、还书、查询逾期。
- 策略模式：不同会员等级使用不同借阅策略。
- 仓储层：使用内存仓储即可，但接口要清晰，方便以后替换为数据库。

## 设计约束

- 实体对象要有合理的 `__repr__` 或 `__str__`。
- 不允许把所有逻辑写进一个类。
- 业务规则放在服务或策略中，不放在 CLI 展示代码中。
- 测试中不要依赖全局状态。

## 测试要求

- 至少 18 个测试用例。
- 必测场景：借出已借图书、超过借阅上限、还不存在的借阅、逾期判断、不同会员策略。
- 对核心服务写参数化测试。

## 阶段拆分

1. **建模阶段**：先定义实体和枚举，不写业务流程。
2. **规则阶段**：实现普通会员和高级会员的借阅策略。
3. **服务阶段**：实现注册、添加图书、借书、还书、逾期查询。
4. **测试阶段**：先测实体，再测策略，最后测服务流程。
5. **复盘阶段**：在 README 说明哪些逻辑放在实体里，哪些放在服务里，为什么。

## 完成定义

这个项目完成时，你应该能解释清楚：

- 类、数据类、枚举分别解决什么问题。
- 为什么会员等级差异适合用策略模式表达。
- 仓储接口和业务服务之间如何分工。
- 如果以后换成数据库，哪些代码应该保持不变。
- 什么时候 OOP 会让代码更清晰，什么时候只是过度设计。

## 验收清单

- [ ] 策略模式不是摆设，至少两个策略行为不同。
